# Coolify 使用教程

搬完以后，日常怎么用 Coolify。按 v4.5.0 写，菜单名用装了[汉化脚本](../coolify-zh/)后的中文，括号里是英文原名。

## 先认识一下结构

Coolify 里的东西是一层套一层的：

```
团队（Team）
└── 项目（Project）           比如“我的服务”
    └── 环境（Environment）   比如 production
        └── 资源（Resource）   一个应用、一个数据库、或一组 Compose 服务
```

另外几样是全局的：

- **服务器（Servers）**：你的机器。装 Coolify 的那台叫 `localhost`。
- **代码来源（Sources）**：连好的 GitHub App。
- **密钥与令牌（Keys & Tokens）**：SSH 私钥、API 令牌等。
- **设置（Settings）**：整个实例的设置，只有管理员能改。

左上角的**搜索**（按 `/` 或 `Ctrl+K`）可以直接搜到任何资源，比一层层点快得多。

## 看状态

- **仪表盘（Dashboard）**：最近的部署，成功还是失败一眼能看到。
- **项目 → 环境**：这个环境下所有资源的列表，状态一栏显示运行中（Running）、已退出（Exited）、不健康（Unhealthy）等。
- 状态写着“运行中（未配健康检查）”的，意思是程序在跑，只是你没配健康检查，**不影响使用**。想让 Coolify 能判断“程序真的能响应”，可以在 健康检查（Healthcheck）里配一个。

## 一个应用页面里有什么

点进一个应用，左边是一排分区，常用的：

| 分区 | 干什么 |
|---|---|
| 通用（General）/ 配置 | 名字、构建方式、根目录、Dockerfile 位置、端口 |
| 域名（Domains） | 加域名、删自动生成的 sslip.io 地址、www 跳转、维护模式 |
| 环境变量（Environment Variables） | 加、改、删变量；开发者视图可以整段粘贴 |
| 持久存储（Persistent Storage） | 数据卷、文件挂载 |
| 高级（Advanced） | 构建缓存、推送自动部署、Git 子模块、容器命名、日志转发、网络别名 |
| 部署日志（Deployment Logs） | 每次部署的构建过程 |
| 运行日志（Runtime Logs） | 程序跑起来以后打出来的日志 |
| 终端（Terminal） | 直接进容器敲命令 |
| 文件（Files） | 浏览、编辑容器里的文件 |
| 计划任务（Scheduled Tasks） | 按 cron 定时在容器里跑命令 |
| Webhook | 外部服务触发部署的地址 |
| 资源限制（Resource Limits） | 限制 CPU、内存 |
| 回滚（Rollback） | 退回之前的镜像版本 |
| 危险操作区（Danger Zone） | 删除应用 |

右上角是操作按钮：部署 / 重新部署、重启、停止，以及“链接”（打开这个应用的域名）。

## 常见操作

### 改了代码，想让它上线

连了 GitHub App 并开着“推送即部署”的话，推到对应分支就会自动部署，什么都不用点。

没开自动部署、或者是按公开仓库部署的：进应用，点右上角 **部署**。

### 改了环境变量

环境变量改完**不会自动生效**，要重新部署一次（或至少重启）。改完点右上角的 **重新部署**。

### 部署失败了

1. 打开 部署日志（Deployment Logs），从下往上找第一个红色的错误；
2. 构建阶段就失败的，多半是构建方式、根目录、Dockerfile 位置不对，或者缺构建时需要的环境变量；
3. 构建成功但跑不起来的，看 运行日志（Runtime Logs），多半是端口不对、环境变量缺了或多了引号；
4. 怀疑是缓存的问题：重新部署的下拉菜单里有“重新部署（不用缓存）”。

### 改坏了，想退回去

进 回滚（Rollback），选之前成功的那个镜像，点“回滚到此镜像”。回滚直接用旧镜像，不重新构建，很快。

能回滚多少个版本，取决于 回滚 页里“保留镜像数”的设置，以及服务器 Docker 清理里“应用镜像”那一项：选“保留镜像”会按各应用的保留数量来；选“删除所有旧镜像”就只剩正在运行的那个，没法回滚了。

### 想进容器里看看

应用 → 终端（Terminal），选容器，就能敲命令了。顶部菜单的 终端 里也能选任意服务器或容器。

### 定时任务

应用 → 计划任务（Scheduled Tasks）→ 新建。频率可以填 `hourly`、`daily` 这类预设，也可以填 cron 表达式。命令会在容器里执行。

### 临时关站维护

应用 → 域名 → 维护模式，打开后所有域名显示维护页（返回 503），容器照常运行，不用重新部署。

## 服务器页

服务器（Servers）→ localhost，常用的：

- **代理（Proxy）**：Traefik 的状态，可以重启、停止、看日志。改了代理配置后要重启代理才生效。重启期间所有网站都打不开，挑没人用的时候做。
- **Docker 清理（Docker Cleanup）**：清理频率和规则。**未使用的卷保持“保留”。**
- **指标（Metrics）/ 流量分析（Analytics）**：要先启用 Sentinel，才能看到 CPU、内存和访问量。启用流量分析会重启 Sentinel 和代理，应用会短暂中断。
- **安全 → 补丁（Security → Patches）**：系统软件包更新。

## 通知

通知（Notifications）里可以接邮件、Telegram、Discord、Webhook 等，选哪些事件要通知：部署失败、服务器磁盘快满、服务器不可达、备份失败等。建议至少开一个，出事了能第一时间知道。

## 设置里值得看一眼的

- 设置 → 通用：面板域名、实例时区。
- 设置 → 高级：注册开关、危险操作是否要两步确认、API 和 MCP 开关。
- 设置 → 更新：自动更新开关和时间。

## 小技巧

- **中文界面**：装本仓库的[汉化脚本](../coolify-zh/)，右下角按钮可以随时切回英文。
- **改设置后看一眼有没有保存**：很多设置页改完要点“保存更改”，页面上会提示“有尚未保存的更改”。
- **点“停止”会删容器**：停止应用时，Coolify 会把已退出的容器删掉。数据在卷里不受影响，但想往容器里拷文件时要注意（第 06 步“恢复数据”）。
- **让 AI 帮你看状态**：Coolify 4.5.0 自带 MCP 端点，配一个只读令牌，就能让 AI 助手直接帮你查哪个服务挂了、部署日志报了什么错。见[小妙招](10-小妙招-让AI替你部署.md)。

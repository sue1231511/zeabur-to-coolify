# 服务器监控：用 Beszel 看核数、内存、磁盘

装了 Coolify，自然想在面板上看到服务器的状态：几个核、多少内存、磁盘用了多少、还剩多少、每个服务各吃多少。

Coolify 本身做不到这么全。它的 **指标（Metrics）** 只有两条曲线：CPU 用了百分之几、内存用了百分之几（见 [Coolify 官方文档](https://coolify.io/docs/core/observability/monitoring/metrics)）。核数、总内存、磁盘用量、每个容器的占用，它都不显示。

我们的办法是在 Coolify 里一键装一个开源的监控面板 **[Beszel](https://github.com/henrygd/beszel)**。装完是一个独立网页，能看到：

- CPU 型号、分到几个核，总内存
- CPU、内存、磁盘的用量和历史曲线
- 每个容器各自的 CPU、内存、网络
- 系统负载、磁盘读写、网络流量，也能设告警

它看不到的一样东西：**磁盘具体被谁占了**（哪个数据卷、哪个镜像占了几个 G）。这个要用命令查，见文末。

## 要不要维护

基本不用。

- Coolify 的 Beszel 模板把版本**锁死**了（我们装的时候是 `0.18.7`），不会自己升级，也就不会哪天自己升坏。想升级时改版本号、重新部署即可，不升也能一直用。
- Coolify 每天的自动更新只更新 Coolify 自己，不会动已经装好的服务。
- 它只存监控曲线，数据量很小。

## 装之前知道一件事

采集程序（beszel-agent）要读 Docker 的状态才能知道每个容器的占用，所以模板把 Docker 的控制接口 `/var/run/docker.sock` 挂给了它。模板里写的是只读挂载，但对这个接口来说，只读其实拦不住它发命令，等于它拿到了 Docker 的管理权限。

Coolify 自己就是这么管容器的，监控工具也基本都这样，不是 Beszel 特有的问题。它开源、用的人多、版本锁死，我们觉得可以接受。介意的话就别装。

## 步骤

### 1. 一键创建

Coolify → 项目 → 环境 → **新建资源** → 搜 `Beszel` → 选 **Beszel**（不是 Beszel Agent，那个是只装采集程序、连别处面板用的）。

会建出一个服务，里面两个容器：`beszel`（面板）和 `beszel-agent`（采集程序）。

### 2. 配域名

服务 → **域名（Domains）**：

- 填 `https://status.你的域名.com`，端口 **8090**（Beszel 面板的端口）。
- 自动生成的 `sslip.io` 地址删掉。删除确认框里“顺带删除 DNS 记录”**不要勾**。
- 可以顺手选 **Noindex**，不让搜索引擎收录。

然后点 **部署**。

此时 `beszel` 应该是“运行中/健康”，`beszel-agent` 会**反复重启**。这是正常的，它还没拿到密钥，Coolify 官方文档也写了这一点。

### 3. 马上建管理员账号

打开 `https://status.你的域名.com`，**立刻**建管理员账号。

这一步别拖：它挂在公网上，在你建好账号之前，谁先打开谁就能注册成管理员。密码设长一点。

### 4. 添加系统，拿到公钥和令牌

面板里点 **添加系统**：

- **名称**：随便，比如服务器的名字。
- **主机 / IP**：填 `/beszel_socket/beszel.sock`。Coolify 模板里，面板和采集程序是通过这个文件通信的。我们实测这样填能连上。（Coolify 文档里写的是填 `beszel-agent`，我们没用这个。）
- 弹窗里会给出一串 **公钥**（`ssh-ed25519` 开头）和一串 **令牌**。

**这个弹窗先别关，也别点“添加系统”。** 先做第 5 步。

### 5. 把公钥和令牌粘进 Coolify

开一个新标签页：Coolify → 这个 Beszel 服务 → **环境变量（Environment Variables）**：

- `KEY` 的值：粘**公钥**。
- `TOKEN` 的值：粘**令牌**。
- 其他选项保持默认，点 **Update Variable** 保存。保存后刷新页面，确认值还在。

### 6. 回到弹窗点“添加系统”，然后重启

回到 Beszel 的弹窗，点最底下的 **添加系统**，再回 Coolify 把这个服务 **重启** 一次。

一两分钟后，面板里这台服务器会变成“在线”，数据开始进来。

## 踩过的坑

- **令牌对不上，采集程序日志里一直是 `unexpected status code: 401`。**
  原因是弹窗里还没点“添加系统”就把它关了（或者刷新了页面）。面板里根本没有这台机器，它不认这个令牌；而且下次打开弹窗会生成一个**新令牌**。
  解决：重新打开“添加系统”，名称、主机照填，把**新令牌**重新粘进 Coolify 的 `TOKEN`（公钥是面板固定的，`KEY` 不用改），点“添加系统”，再重启服务。
- **采集程序日志里出现一次 `503`**：面板刚重启还没起来，等十几秒就好，不用管。
- **CPU 型号写着 “48-Core Processor”**：这是整颗 CPU 的型号名，不是你分到的核数。你分到几个核，看面板里的核数 / 线程数。
- **容器名是一串乱码**：Coolify 建的容器用随机 ID 命名，Beszel 显示的就是这个 ID。到 Coolify 的资源页对一下 ID 开头就知道是谁。想改成可读的名字，可以在应用的“高级”设置里改容器命名，但每个应用都要重新部署一次，我们没改。
- **“健康”一栏显示 None**：意思是那个应用没配健康检查，Beszel 判断不了，不是坏了。
- **`buildx_buildkit_...` 这个容器很占内存**：它是 Coolify 用 Railpack 构建时拉起来的构建工具，构建完也一直挂着，大约占两三百 MB，不影响服务。
- **Coolify 网页里改域名、改设置怎么都存不上**：页面顶上有一行 “Cannot connect to real-time service” 时，弹窗保存经常不生效，终端也连不上。我们最后是让 AI 通过 Coolify 自带的 MCP 改的，见[小妙招](10-小妙招-让AI替你部署.md)。

## 磁盘到底被谁占了

Beszel 只告诉你磁盘用了多少，不拆账。想知道具体被谁占了，SSH 登录服务器，把下面这段整个粘进去。这些命令只查看，不修改任何东西：

```
echo "== CPU 核数 =="; nproc; lscpu | grep "Model name"
echo "== 内存 =="; free -h
echo "== 磁盘总量 =="; df -h /
echo "== Docker 占用总览 =="; docker system df
echo "== 数据卷占用 前15 =="; du -sh /var/lib/docker/volumes/* 2>/dev/null | sort -rh | head -15
echo "== 镜像占用 前15 =="; docker images --format '{{.Size}}\t{{.Repository}}:{{.Tag}}' | sort -rh | head -15
echo "== 根目录大户 前10 =="; du -xsh /* 2>/dev/null | sort -rh | head -10
```

不是 root 用户登录的，最后几行前面加 `sudo`。

看结果时，一般是旧镜像和构建缓存占得最多，可以用 Coolify 服务器页的 **Docker 清理（Docker Cleanup）** 清。**数据卷别乱删**，那里面是你的数据。

# 小妙招：让 AI 替你部署

十几个服务，每个都要“新建 → 选仓库 → 选构建方式 → 填端口 → 删 sslip.io 地址 → 设别名……”，一个一个点下来很磨人。

猫猫一开始是自己一个个部署的。后来换了个办法：**让 AI 打开浏览器，进 Coolify 面板替她建服务，她睡觉；醒来只做一件事——把环境变量粘进去。**

## 分工

| 谁 | 做什么 |
|---|---|
| AI | 在 Coolify 里新建服务、选仓库和分支、选构建方式、填根目录和端口、填域名或删掉 sslip.io 地址、设网络别名、加持久存储；把每个服务需要哪些环境变量列成清单（只列名字，不列值） |
| 你 | 粘贴环境变量的值、点部署、看结果；所有删除、停止、改设置的操作由你点头 |

环境变量是全部密钥所在，这一块**始终由你自己粘贴**。AI 只负责把“壳子”搭好。

## 需要什么

- 一个**能操作浏览器的 AI**。我们用的是 Claude，它可以在自己的浏览器窗格里打开网页、点按钮、读页面。别的能控制浏览器的 agent 也行。
- 在那个浏览器里**你自己登录**好 Coolify 面板。密码你自己输，不交给 AI。
- 第 02 步的服务清单（服务名、仓库、子目录、构建方式、端口、要不要公网域名）。清单越清楚，AI 越不容易建错。

## 给 AI 的规矩

开始前把这几条说清楚：

1. **只建不删。** 新建、填写、保存可以做；删除任何东西、停止服务、改实例设置，先问我。
2. **不碰密钥。** 不往任何输入框里填密码、令牌、API key。环境变量那一页只看变量名，不填值。
3. **建一个报一个。** 每建好一个服务，报告：用了什么构建方式、端口、域名或别名、还差哪些环境变量。
4. **不确定就停下问**，别猜。比如端口不确定，宁可空着等我确认。

## 一份可以直接用的提示词

```text
我在你的浏览器里已经登录了 Coolify 面板：https://coolify.<你的域名>.com
请按下面的服务清单，在项目 <项目名> 的 production 环境里逐个新建服务。

规矩：
- 只新建和保存，不删除、不停止任何东西，不改实例设置；需要的话先问我。
- 不往任何输入框里填密码、令牌、API key。环境变量页只记下需要哪些变量名，不填值。
- 有 Dockerfile 的选 Dockerfile，没有的选 Railpack；端口按清单填，清单里没写的空着问我。
- 要公网域名的，填 https://服务名.<你的域名>.com；只给内网用的，删掉自动生成的 sslip.io 地址
  （删除时不要勾“删除 DNS 记录”），不填端口映射，在网络别名里填清单给的别名。
- 每建好一个，告诉我：构建方式、端口、域名或别名、需要我粘贴的环境变量名清单。
- 遇到不确定的就停下问我，不要猜。

服务清单：
<粘贴你的清单>
```

## 你醒来以后

1. 看 AI 的报告，逐个服务核对一遍设置；
2. 按它列的变量名，把第 03 步备份的值粘进 环境变量 页的开发者视图（注意第 06 步的七条规则）；
3. 点部署，看部署日志和运行日志；
4. 有数据的服务，按第 06 步“恢复数据”把备份放进卷里，这一步也可以让 AI 在服务器上帮你执行，但每条命令先给你看。

## 让 AI 帮你盯着：Coolify 的 MCP

Coolify 4.5.0 自带一个 MCP 端点（`/mcp`），配上令牌以后，AI 助手可以直接查询你的服务器、项目、应用、部署和日志，不用再开浏览器截图。

1. 设置 → 高级 → API and MCP，把 MCP server 改成已启用，保存；
2. 密钥与令牌 → API 令牌，新建一个令牌：
   - **权限只给 Read**。只是查状态，用不着部署和写入权限；
   - **不要勾 Read sensitive data**，那会让 AI 能看到环境变量里的密码；
   - 设一个过期时间，比如 30 天；
3. 在你的 AI 客户端里添加这个 MCP，地址 `https://coolify.<你的域名>.com/mcp`，请求头 `Authorization: Bearer <令牌>`。令牌由你自己填进客户端的配置里，不要贴进聊天。
   - 你的客户端要支持给 MCP 填自定义请求头。不支持的话，可以通过一个支持请求头的 MCP 聚合工具中转。

以后问一句“哪个服务挂了”“刚才那次部署为什么失败”，它就能自己去查。

## 给 agent 的附加说明：页面点不准时

有时 AI 操作浏览器会遇到窗口被挡住、截图是旧的、点不中按钮的情况。Coolify 的界面是 Livewire 写的，我们当时的变通办法是让 AI 直接调用页面里组件的方法，比如选仓库 `set('selected_repository_id', N)` 再 `call('loadBranches')`，改构建方式和端口 `set('build_pack', …)`、`set('port', …)`。

这属于进阶用法：

- 这些方法名是 Coolify 内部实现，**版本一升级就可能变**，用之前让 AI 先在页面里确认存在；
- 通过这种方式改了输入框的值，**一样要点“保存更改”**；
- 删除类的操作（比如删域名）同样要先问你，删 sslip.io 地址时同样不能顺带删 DNS 记录。

能正常点的时候，优先正常点。

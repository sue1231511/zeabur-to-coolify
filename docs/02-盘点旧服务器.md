# 02 盘点旧服务器

先搞清楚旧机上有什么，再决定带走什么。这一步**只看不改**，让 agent 去查，你跟助手一起看报告。提示词见[给 agent 的提示词模板](12-给agent的提示词.md)第 1 段。

## 怎么登旧机（Zeabur 租的服务器）

- root 密码在**当初购买时发到你邮箱**里了。
- 忘了的话，在 Zeabur 后台这台服务器页面点 **Reset SSH password**，新密码会发到邮箱。
- 也可以用 Zeabur 命令行：`npx zeabur@latest server ssh`（电脑上要先装 Node.js，并 `npx zeabur@latest auth login` 登录）。
- **给 agent 开权限的推荐做法**：让 agent 生成一把专用的 SSH 公钥，**你自己**在 Termius 里把它追加进旧机的 `/root/.ssh/authorized_keys`。**不要把密码贴给 agent。** 搬完记得把这把公钥删掉（第 08 步）。

## 要查清的东西

1. 每个项目有哪些服务、各是什么镜像、代码在不在 GitHub 上。
2. 每个存档盘（数据卷）是谁的、多大、最近有没有在写入。路径在 `/var/lib/rancher/k3s/storage/`。
3. **有没有“无主”的存档盘**：服务被 Zeabur 暂停后会删掉服务本体，但存档盘还在。别漏了。
4. 每个服务的环境变量名，哪些是从别的服务自动注入的、哪些写着 `.zeabur.internal` 或 `.zeabur.app` 地址。
5. **Zeabur 以外的东西**：你自己 SSH 进去装的 Docker 容器（`docker ps -a`）、系统服务（比如自建代理）、`/root` 下的脚本。这些 Zeabur 后台根本看不到，最容易漏。
6. 硬盘总占用。

## 看报告时注意

服务器上的名字跟后台显示的经常对不上。服务在服务器上叫 `service-一串编号`，项目名是你最初建项目时的名字（比如后台叫 `my-bot`，服务器上叫 `bot-abcd`）。对不上的，用域名或者环境变量里的地址去认，再不行就打开后台对一下。

## 把盘点结果变成一张清单

建议每个服务一行，记下这些，后面每一步都要用：

| 列 | 说明 |
|---|---|
| 服务名 | 后台的名字，以及服务器上对应的名字 |
| 代码在哪 | GitHub 仓库地址，是不是在子目录里 |
| 怎么构建 | 有没有 Dockerfile；没有的话是什么语言 |
| 端口 | 程序实际监听的端口 |
| 环境变量 | 有几个，存到哪个备份文件里了 |
| 数据 | 有没有数据库、有没有往硬盘写文件 |
| 对外地址 | 用的是 `*.zeabur.app` 还是自己的域名 |
| 谁在调用它 | 别的服务、机器人、App 里有没有写死它的地址 |

最后一列最容易漏。服务 A 搬走了，服务 B 里还写着 A 的旧地址，B 就会悄悄坏掉。

# 03 备份

> **这是整个搬家里最重要的一步。** 服务部署坏了可以重来，数据丢了就真的没了。旧机到期那天，硬盘会连机器一起被删，Zeabur 自己的每日备份也会跟着关停一起消失。

原则只有一条：**只存在旧服务器硬盘上的东西，全部打包下载到你电脑，并且核对过。** 代码在 GitHub 上的不用管，新平台会从 GitHub 重新构建。

提示词见[给 agent 的提示词模板](12-给agent的提示词.md)第 2 段。

## 要带走什么、怎么带

| 要带走的 | 怎么备份 | 注意 |
|---|---|---|
| 存档盘（数据卷） | 打包 `/var/lib/rancher/k3s/storage/` 下对应的文件夹 | 先让 agent 报每个盘多大、谁的 |
| SQLite 数据库 | 用 `sqlite3 .backup` 安全导出；服务器没装 sqlite3 就用 Python 自带的 `sqlite3.backup()` | 正在写入的数据库**不要直接复制文件**，可能打出坏包 |
| MariaDB / PostgreSQL | 用同大版本的官方工具导出：`mariadb-dump`、`pg_dump` | Zeabur 每天的自动备份会跟着关停一起消失，要自己导 |
| 环境变量 | 每个服务导出一份 deploy yaml（里面是展开后的真实值），或在 Zeabur 后台用原始文本模式整段复制 | 全是密钥，只存本机；后台显示的 `${...}` 引用是没展开的 |
| 不在 GitHub 上的服务 | 导出正在运行的镜像：`k3s ctr -n k8s.io images export` | Zeabur 镜像仓库关停后就拉不到了 |
| 你自己装的 Docker 容器 | 先记下启动配置（`docker inspect`），停容器，打包它的卷，再启动回去 | 比如 QQ 机器人，卷里有登录状态 |
| 自建代理、系统服务 | 打包它的配置文件夹 + systemd 服务文件 | 代理的私钥也在里面 |
| `/root` 下的脚本 | 先列出来看一眼，有用的打包 | `.bash_history` 可能有密码，别带 |

### SQLite 安全导出的写法

```bash
# 有 sqlite3 命令时
sqlite3 /路径/data.db ".backup '/root/backup/data.db'"

# 没有 sqlite3，用 Python 自带的
python3 -c "import sqlite3; s=sqlite3.connect('/路径/data.db'); d=sqlite3.connect('/root/backup/data.db'); s.backup(d); d.close(); s.close()"
```

## 下载和核对

1. 让 agent 把所有备份下载到你电脑上**一个专门的文件夹**，敏感文件只给你自己的账户读。
2. **逐个核对**，三项都要过：
   - SHA256 跟服务器上一致；
   - 压缩包能列出内容（`tar -tzf 文件名.tar.gz`）；
   - SQLite 跑一遍 `integrity_check`，结果是 `ok`。

```bash
# 在旧服务器上
sha256sum data.db
# 下载到电脑以后再算一次，两边结果必须一模一样
sha256sum data.db          # macOS / Linux
Get-FileHash data.db -Algorithm SHA256   # Windows PowerShell

# SQLite 完整性
sqlite3 data.db "PRAGMA integrity_check;"
```

3. 能拷一份到 U 盘就拷，**别传网盘**：里面有你所有服务的密钥。

## 另买新机的好处：最后再同步一次

第一次备份是拿来在新机上测试的。等新机都测通、准备正式切换时：

1. 先停掉旧机上会写数据的服务；
2. **再备份一次最新的数据**带过去；
3. 核对，恢复到新机，再启动新机上的服务。

不然第一次备份之后到切换之间写进去的东西会丢。

## 在新家真的恢复一次

官方搬家指南也强调：备份不等于能用。把备份**实际恢复到新机**（第 06 步有命令），打开服务确认数据都在，才算这份备份是好的。

## 到了新家以后，备份也要接着做

搬完不是终点。新机同样可能出问题，尤其是不支持快照的机房：

- **Coolify 自己的密钥**：备份 `/data/coolify/source/.env`，里面有 `APP_KEY` 等，丢了很麻烦。和上面的备份放一起，同样只存本地。
- **数据库**：Coolify 里的数据库资源有 备份（Backups）页，可以设定时备份。只存在同一台服务器上不算真正的备份，最好再配一个 S3 兼容的存储，或者定期下载回本地。
- **写硬盘的服务**：定期把数据卷打包拷回本地，同样核对 SHA256。

## 检查清单

- [ ] 每个存档盘都备份了，包括“无主”的
- [ ] 每个 SQLite 用 `.backup` 导出，`integrity_check` 是 `ok`
- [ ] 每个 MariaDB / PostgreSQL 用 dump 工具导出
- [ ] 每个服务的环境变量都有一份带真实值的文件
- [ ] 不在 GitHub 上的服务，镜像导出了
- [ ] Zeabur 以外的容器、代理、系统服务、`/root` 脚本都检查过
- [ ] 所有文件 SHA256 跟服务器上一致
- [ ] 备份只在本机和 U 盘，没有上网盘
- [ ] 正式切换前，停写、再同步一次
